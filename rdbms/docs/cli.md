# `hwdb` 명령 (데몬 제어와 SQL 접속)

`hwdb` 하나로 데몬의 구동·종료·상태 조회와 SQL 접속을 모두 한다. 사양은 AGENTS.md 상세 14, 15이고, 이 문서는 구현이 정한 세부와 동작을 적는다.
구현은 `src/cli`(명령), `src/daemon/entry.ts`(분리된 데몬의 진입점), `src/client`(접속 라이브러리)이다.

## 1. 기본 규칙

- 설치 디렉토리는 `hwdb` 가 속한 `rdbms` 디렉토리이다. config.json 도 거기서 읽는다. 시험에서는 환경 변수 `HWDB_INSTALL_DIR` 로 바꾼다.
- `start`, `stop`, `status` 는 그 설치 디렉토리의 인스턴스를 다룬다. SQL 접속은 포트 번호로 인스턴스를 가리킨다(상세 15). 포트를 생략하면 설치 디렉토리 config.json 의 `port` 이다.
- 화면 문구는 영어이고 메시지 카탈로그(`src/cli/messages/en.ts`)에서 꺼낸다. 언어는 `HWDB_LANG`, `LC_ALL`, `LC_MESSAGES`, `LANG` 순서로 고르고, 카탈로그가 없으면 영어이다. 서버가 보낸 DB 오류 메시지는 번역하지 않는다(상세 0).
- 결과(조회 결과 표, 완료 메시지)는 표준 출력, 오류·안내·경고는 표준 오류에 낸다.
- 종료 코드는 정상 0, 실패 1이다. 명령행 오류도 1이다.

## 2. 데몬 제어

| 명령 | 동작 | 종료 코드 |
|---|---|---|
| `hwdb start [--timeout 초] [--foreground]` | 데몬을 분리된 프로세스로 띄우고, 접속을 받을 수 있게 되면 포트 번호와 PID 를 알리고 끝난다 | 성공 0, 실패 1. 이미 구동 중이면 그 사실을 알리고 0 |
| `hwdb stop [--timeout 초]` | 종료를 요청하고, 정상 종료 절차가 끝나 프로세스가 사라질 때까지 기다린다 | 성공 0, 실패 1. 구동 중이 아니면 그 사실을 알리고 0 |
| `hwdb status` | 구동 여부, 포트, PID, 구동 시각, 버전, 데이터 디렉토리, TCP·UDP 사용 여부, 세션 수를 보여 준다 | 구동 중 0, 아니면 1 |

`--timeout` 의 기본은 30초이고 양의 정수만 받는다(`--timeout 5`, `--timeout=5`).

### 2-1. 구동 중인지 아는 방법

잠금 파일(`<dataDir>/helloworlddb.lock`)의 PID 가 살아 있다는 것만으로는 구동 중이라고 할 수 없다. 운영체제는 끝난 데몬의 PID 를 다른 프로그램에 다시 줄 수 있다.
그래서 CLI 는 잠금 파일의 제어 토큰으로 로컬 전용 채널에 상태를 물어 **답이 오는 것**을 구동 중으로 본다(`probeDaemon`). 접속은 잠금 파일에 적힌 포트로 한다.
구동한 뒤에 config.json 의 `port` 를 바꿔도(설정은 구동할 때 한 번만 읽는다) 떠 있는 데몬을 찾아 상태를 보고 종료할 수 있다.

| 상태 | 판정 | `start` | `stop` | `status` |
|---|---|---|---|---|
| 구동 중 | 로컬 전용 채널이 상태 조회에 답한다 | "이미 구동 중" 안내, 0 | 종료 요청 | 값을 보여 주고 0 |
| 구동 중이 아님 | 잠금 파일이 없거나 PID 의 프로세스가 없다(남은 잠금 파일은 구동할 때 덮어쓴다) | 구동 | "구동 중이 아님" 안내, 0 | `running: no`, 1 |
| 답 없음 | PID 는 살아 있는데 로컬 전용 채널이 답하지 않는다 | 아래 참고 | 오류, 1 | `running: no` 와 안내(`note:`), 1 |

"답 없음"은 구동 중이거나, 멈췄거나, PID 를 다른 프로그램이 쓰는 중일 수 있다. 잠금 파일을 마음대로 지우지 않고 알려 준다.
`start` 는 잠금 파일의 구동 시각이 60초 이내이면 다른 `hwdb start` 가 막 띄운 데몬으로 보고 제한 시간까지 기다리고, 그보다 오래되었으면 잠금 파일 경로와 PID 를 알리며 실패한다. (그 프로세스가 데몬이 아니면 관리자가 잠금 파일을 지우고 다시 시도한다)

### 2-2. `hwdb start` 의 동작

1. config.json 을 읽는다. 올바르지 않으면 원인을 보여 주고 1로 끝난다.
2. 구동 상태를 확인한다(2-1). 이미 구동 중이면 알리고 0으로 끝난다.
3. `process.execPath`(Node.js 또는 bun)로 `daemon/entry.js` 를 **분리된 프로세스**(`detached`)로 띄운다. 표준 입력은 닫고, 표준 출력과 표준 오류는 로그 파일(`<log.dir>/helloworlddb.log`)에 이어 붙인다.
   Windows 에서는 `windowsHide` 로 콘솔 창이 뜨지 않게 한다. 데몬은 콘솔에 붙어 있지 않으므로 터미널을 닫아도 영향이 없다. 유닉스 계열에서는 새 세션으로 분리되고 SIGHUP 은 무시한다.
4. 0.1초마다 확인한다 : 데몬이 끝났으면 실패, 잠금 파일이 그 PID 를 가리키고 로컬 전용 채널의 상태 조회가 `ready: true`(모든 접속 경로가 열림)이면 성공이다.
5. 성공하면 `HelloWorldDB started. port: <포트>, pid: <PID>` 를 쓰고 끝난다. SYSTEM 계정이 초기 암호이면 변경 안내를 표준 오류에 함께 낸다.
6. 실패하면 로그 파일의 이번 구동 분량에서 원인(마지막 `[error]` 줄)을 찾아 `hwdb start: <원인>` 과 로그 파일 경로를 보여 주고 1로 끝난다. 제한 시간 안에 끝나지 않아도 실패이며, 그때는 구동 중이던 데몬에 정상 종료를 요청하고 5초 안에 끝나지 않으면 강제로 끝낸다.

`--foreground` 는 분리하지 않고 현재 터미널에서 실행한다(개발, 시험, 서비스 관리자 등록용). 로그가 터미널에도 나오고 SIGINT/SIGTERM 또는 `hwdb stop` 으로 끝난다.

### 2-3. `hwdb stop` 의 동작과 종료 지연 방지

로컬 전용 채널로 종료 요청(`control stop`)을 보내고 `stopping` 응답을 받은 뒤, 잠금 파일의 PID 가 사라질 때까지 0.1초마다 확인한다. Windows 에서는 다른 프로세스가 보낸 SIGTERM 을 받을 수 없으므로 이 요청이 종료의 기본 경로이다.

데몬은 종료할 때 접속한 클라이언트에 종료 오류(`57P01`)를 보내고 최대 2초 기다린 뒤 남은 소켓을 닫는다. 그런데 클라이언트가 소켓을 읽지도 닫지도 않으면(멈춘 프로그램 등)
특히 Windows 의 네임드 파이프는 서버 쪽 닫기가 끝나지 않아 이벤트 루프가 비지 않고 프로세스가 남는다. 정상 종료 절차(데이터 파일 반영, 정상 종료 표시, 잠금 파일 제거)를 마친 뒤
`daemon/main.ts` 의 `exitAfterShutdown` 이 표준 출력·오류를 비우고 직접 프로세스를 끝내므로 `hwdb stop` 은 최대 약 2초 뒤에 끝난다. (`test/cli/daemonLifecycle.test.ts`)

### 2-4. 잠금 파일

`acquireLock` 이 구동할 때 PID, 포트, 구동 시각, 제어 토큰을 적는다(`daemon/lockFile.ts`). 잠금 파일을 만드는 짧은 구간은 가드 디렉토리(`helloworlddb.lock.acquire`)로 직렬화한다.
그 구간(수 ms)에 프로세스가 강제 종료되어 남은 가드는 10초가 지나면 오래된 것으로 보고 치운 뒤 구동한다. 10초 이내의 가드는 다른 프로세스가 지금 구동 중인 것으로 보고 구동에 실패한다.

## 3. SQL 접속

`hwdb [옵션]`. 모든 옵션을 생략할 수 있다. 값이 필요한 옵션은 `--port 7410`, `--port=7410`, `-P 7410`, `-P7410` 형태를 모두 받는다. 짧은 옵션은 모두 값을 받는다.

| 옵션 | 생략했을 때 | 설명 |
|---|---|---|
| `-h`, `--host` | 로컬 전용 채널 | 지정하면 그 주소에 TCP 로 접속 |
| `-P`, `--port` | config.json 의 `port` | 인스턴스의 포트 번호 |
| `--udp` | TCP | `--host` 와 함께 써서 UDP 로 접속 |
| `--ssl` | 평문 | TCP 접속에 SSL 사용. 서버 인증서를 기본으로 검증한다 |
| `--ssl-ca <파일>` | 운영체제와 Node.js 의 기본 CA | 서버 인증서를 검증할 CA 인증서(PEM). 자체 서명 인증서를 쓰는 서버는 그 인증서를 지정한다 |
| `--ssl-no-verify` | 검증한다 | 서버 인증서 검증을 끈다(안전하지 않다) |
| `-u`, `--user` | 물어본다 | 사용자명 |
| `-p`, `--password` | 화면에 보이지 않게 물어본다 | 비밀번호 |
| `-t`, `--tablespace` | 사용자의 기본 테이블스페이스 | 접속 직후의 현재 테이블스페이스. SQL 식별자 규칙을 따른다 : `-t app` 은 `APP`, `-t '"MixedCase"'` 는 `MixedCase` |
| `-e`, `--execute` | 대화형 모드 | 문장을 실행하고 종료 |
| `-f`, `--file` | 대화형 모드 | 파일의 문장을 차례로 실행하고 종료 |
| `--version`, `--help` | | 버전, 사용법 |

조합 규칙(어기면 오류 1) : `--udp`, `--ssl`, `--ssl-ca`, `--ssl-no-verify` 는 `--host` 와 함께만. `--udp` 와 `--ssl` 은 함께 쓸 수 없다. `--ssl-ca`, `--ssl-no-verify` 는 `--ssl` 이 있어야 하고 서로 함께 쓸 수 없다. `-e` 와 `-f` 는 함께 쓸 수 없다.
(`src/cli/args.ts`, 시험은 `test/cli/args.test.ts`)

### 3-1. 모드

- **스크립트 모드** : `-e`, `-f` 를 쓰거나 표준 입력이 터미널이 아닐 때. 표준 입력이 터미널이 아니면 사용자명과 비밀번호를 물어볼 수 없으므로 `-u`, `-p` 가 필요하다(없으면 알리고 1).
  입력(문자열, 파일, 표준 입력)은 접속하기 전에 읽는다. UTF-8 이어야 하며(맨 앞의 BOM 은 무시) 아니면 로그인하지 않고 1로 끝난다. 문장을 `;` 로 나누어 하나씩 서버에 보내고, 오류가 나면 거기서 멈추고 1로 끝난다.
  `exit`, `quit`, `help` 는 일반 문장으로 서버에 보낸다. 끝에 `;` 가 없는 마지막 문장도 실행한다.
- **대화형 모드** : 표준 입력이 터미널이고 `-e`, `-f` 가 없을 때. 프롬프트는 `hwdb> ` 이고 문장이 끝나지 않았으면 `    -> ` 이다. `;` 를 만나면 실행하며 한 줄에 문장이 여럿이어도 된다.
  `exit`, `quit`(끝의 `;` 와 대소문자는 무관)로 끝내고 `help` 로 도움말을 본다. Ctrl-D 도 끝낸다. Ctrl-C 는 쓰던 입력을 버린다(입력이 비어 있으면 안내만 한다). 위/아래 화살표로 입력 이력을 불러온다(그 프로세스가 사는 동안만).
  오류가 나도 계속한다. 서버가 접속을 닫으면(서버 종료, 유휴 시간 초과) 오류를 알리고 1로 끝난다. 문장을 쓰는 도중에 입력한 `exit` 는 문장의 일부이다.

### 3-2. 문장 나누기 (`src/cli/statementSplitter.ts`)

`;` 가 문장의 끝이다. 문자열 리터럴(`'a;b'`, `''` 는 따옴표 하나), 큰따옴표 식별자(`"a;b"`), 한 줄 주석(`-- a;b`), 여러 줄 주석(`/* a;b */`, 중첩하지 않음) 안의 `;` 는 끝으로 보지 않는다. SQL 어휘 분석(`sql/lexer.ts`)과 같은 규칙이다.
공백과 주석뿐인 조각은 문장이 아니다. 문장 앞의 주석은 문장과 함께 서버에 보낸다. 서버에는 한 번에 한 문장만 간다.

### 3-3. 사용자명과 비밀번호

생략하면 물어본다. 사용자명은 한 줄 입력, 비밀번호는 터미널을 원시 모드로 바꾸어 글자를 하나씩 받고 화면에 되울리지 않는다(`src/cli/terminal.ts`). 백스페이스로 지우고 Ctrl-C 로 취소한다(취소하면 접속하지 않고 1). 화살표 같은 이스케이프 열은 버린다.
원시 모드를 지원하지 않는 터미널이면 보이는 채로 받지 않고 `-p` 를 쓰라고 안내하며 1로 끝난다.

`-p` 로 준 비밀번호는 운영체제의 프로세스 목록에서 다른 사용자에게 보일 수 있다. 사람이 직접 접속할 때는 물어보게 두는 편이 안전하다.
`-t` 의 이름은 클라이언트가 식별자 규칙으로 바꾸어 보낸다(프로토콜의 `authStart.tablespace` 는 저장된 이름 그대로를 받는다. `tablespaceNameOf`).

SYSTEM 계정이 초기 암호(`HelloWorldDB`)로 로그인하면 변경 안내와 예시 문장(`ALTER USER SYSTEM IDENTIFIED BY '<new password>'`)을 표준 오류에 낸다. 암호를 바꾸면 안내는 사라진다.

### 3-4. 출력

- 조회 결과는 표이다. 열 폭은 표시 폭 기준이라 한글·한자·가나·전각 문자·이모지는 2칸, 결합 문자는 0칸으로 센다. 숫자 타입(정수, `DECIMAL`, 부동소수)은 오른쪽으로 맞춘다. 끝에 `N rows (소요 시간)` 을 덧붙인다.
- **NULL 은 `NULL`, 빈 문자열은 빈 칸**이다. 이진 값은 `0x` 를 붙인다. 줄바꿈, 탭, 그 밖의 제어 문자는 `\n`, `\t`, `\xNN` 으로 바꾸어 표가 깨지지 않게 한다. 큰 결과는 서버에서 나누어 받아 모두 모은 뒤 한 표로 낸다.
- 조회가 아닌 문장은 서버의 완료 메시지에 영향받은 행 수와 소요 시간을 붙인다. 예 : `INSERT 1 (1 row affected, 3 ms)`.
- 오류는 `ERROR [SQLSTATE:내부번호] 메시지` 이다. 위치가 있으면 그 줄과 가리키는 `^` 를 이어서 보이고(한글은 폭만큼 밀린다), 스크립트 모드에서는 입력(파일)에서의 줄과 칸(`at input line 4, column 4`)도 알린다.
  같은 줄에 앞선 문장이 있으면 그 문장이 시작한 칸만큼 반영한다.
- 접속 실패 : 로컬 전용 채널에서 데몬이 없으면 `hwdb start` 를 안내한다. SSL 인증서 검증에 실패하면 클라이언트 라이브러리의 재시도(100 ms 뒤 최대 2회)를 `certificate error (CODE); retrying 1/2 ...` 로 한 줄씩 알리고,
  최종 실패(`08001`)에는 `--ssl-ca`, `--ssl-no-verify` 안내를 덧붙인다. 재시도에서도 검증은 그대로 한다.

### 3-5. 끝낼 때의 롤백 안내

접속을 끝낼 때(`close`) 서버는 커밋하지 않은 변경을 롤백한다. 서버가 `bye` 응답에 `rolledBack: true`(롤백한 변경이 있을 때만)를 실어 알려 주고(프로토콜 6절),
`hwdb` 는 `Uncommitted changes were rolled back.` 를 표준 오류에 낸다. 트랜잭션이 열려 있어도 변경이 없으면(`BEGIN; SELECT 1`, `ROLLBACK TO` 로 모두 되돌림) 알리지 않는다. 오류로 끝났을 때도 같다.

## 4. 설치 직후의 표준 절차

```sh
hwdb start                          # 데몬을 띄운다. SYSTEM 이 초기 암호이면 변경 안내가 함께 나온다
hwdb                                # 로컬 전용 채널로 접속. Username: SYSTEM, Password: HelloWorldDB
hwdb> ALTER USER SYSTEM IDENTIFIED BY '새 비밀번호';
hwdb> exit
```

SYSTEM 에는 CONNECT 권한 그룹이 없으므로 처음에는 로컬(로컬 전용 채널, 루프백)에서만 접속된다. 원격 관리가 필요하면 `GRANT CONNECT TO SYSTEM` 을 한다.
TCP 와 UDP 를 모두 껐거나 `maxConnections` 가 찬 상태에서도 `hwdb` 의 로컬 접속은 항상 된다(상세 14-2).

## 5. 확인 기록과 알려진 한계

- Windows(Node.js 24.19, bun 1.3.14)에서 확인했다 : `hwdb start` 가 약 0.4초 만에 돌아오고, 데몬에 콘솔 창과 자식 콘솔 호스트가 없으며, 새 콘솔 창에서 `hwdb start` 를 실행한 뒤 그 창의 프로세스를 강제로 끝내도 데몬이 남아 `status` 와 `stop` 이 동작한다.
  실제 터미널 앱(Windows Terminal 등)의 탭을 닫는 동작은 자동화하지 못했다. 데몬이 콘솔에 붙어 있지 않으므로 콘솔 닫힘 이벤트가 닿지 않는다고 보지만, 실제 장비에서 한 번 확인한다.
- 대화형 모드의 실제 터미널 동작(비밀번호 숨김, 입력 이력, Ctrl-D, 줄 편집)은 `winpty` 로 만든 진짜 Windows 콘솔에서 사람이 하는 것과 같은 입력을 넣어 확인했다. 자동 시험은 가짜 스트림으로 논리를 본다(`test/cli/terminal.test.ts`, `sqlShell.test.ts`).
- 리눅스, macOS 에서의 `hwdb start`(새 세션으로 분리, SIGHUP 무시)와 유닉스 소켓은 Windows 개발 환경에서 실행해 보지 못했다.
- 결과 전체를 서버와 CLI 가 메모리에 모은 뒤 출력한다(통신 설계 5절). 아주 큰 조회는 메모리를 많이 쓴다.
- 대화형 모드의 입력 이력은 파일에 저장하지 않는다.
- 표시 폭 표는 동아시아 넓은 문자와 대표적인 이모지 범위를 담았다. 글꼴과 터미널에 따라 폭이 다른 문자(모호한 폭), 이음 이모지 순서는 정확하지 않을 수 있다.
