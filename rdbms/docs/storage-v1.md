# 테이블스페이스 포맷 v1

AGENTS.md 상세 2, 3, 10, 12를 구현하는 저장 계층의 명세이다. SQL 타입은 모르는 바이트 저장소이며, SQL 카탈로그와 데몬 연결은 5단계에서 한다. 정수는 별도 표시가 없으면 부호 없는 리틀 엔디언이다. 페이지 번호는 32비트이고 0은 포인터의 없음 표시이다. 파일은 8,192바이트 페이지의 나열이다. 페이지 끝 4바이트는 앞 8,188바이트의 CRC-32/ISO-HDLC이다(반사 다항식 `EDB88320`, 초기값과 최종 XOR `FFFFFFFF`).

## 파일 헤더(0번 페이지)

| 오프셋 | 바이트 | 내용 |
|---|---:|---|
| 0 | 8 | 매직: `48 57 44 42 54 53 0D 0A` (`HWDBTS\r\n`) |
| 8 | 4 | 포맷 버전. v1은 1. 매직과 이 위치는 이후 버전에서도 고정 |
| 12 | 4 | 페이지 크기: 8192 |
| 16 | 16 | 캐릭터셋 ASCII, NUL 채움: `UTF8` |
| 32 | 2 | 이름의 UTF-8 바이트 수 |
| 34 | 2 | 생성 서버 버전의 UTF-8 바이트 수 |
| 36 | 4 | 예약, 0 |
| 40 | 512 | 테이블스페이스 이름, UTF-8, 남은 부분은 0. 최대 128 코드 포인트 |
| 552 | 64 | 생성 서버 버전, UTF-8, 남은 부분은 0 |
| 616 | 8 | 생성 시각, signed int64, Unix epoch 밀리초 |
| 624 | 1 | 정상 종료 표시: 0 실행 중/비정상 종료, 1 정상 종료 |
| 625 | 7 | 예약, 0 |
| 632 | 4 | 카탈로그 바이트열의 첫 오버플로 페이지 |
| 636 | 4 | 빈 페이지 연결 목록의 첫 페이지 |
| 640 | 4 | 헤더를 포함한 전체 페이지 수 |
| 644 | 7544 | 예약, 0 |
| 8188 | 4 | CRC-32 |

포맷을 고를 때 처음 12바이트를 먼저 확인한다. 모르는 버전, UTF8 이외의 캐릭터셋, 잘못된 UTF-8, 부분 페이지, 체크섬 오류는 오류를 반환한다. 상위 계층은 일반 테이블스페이스를 사용 불가로 두고 SYSTEM이면 구동을 실패시켜야 한다(5단계). v1을 열 때 모든 페이지의 체크섬과 공통 헤더를 검증한다. 정상 종료 표시가 0이었으면 경고 콜백을 호출하며 자동 복구하지 않는다. 열기가 완료되기 전에 표시를 0으로 쓰고 fsync한다. 정상 닫기는 미커밋 배치를 버리고 표시를 1로 쓰고 fsync한다. I/O 실패가 발생한 파일은 정상 종료로 표시하지 않는다.

## 데이터 페이지 공통 헤더

| 오프셋 | 바이트 | 내용 |
|---|---:|---|
| 0 | 4 | 자신의 페이지 번호 |
| 4 | 1 | 종류: 1 빈 페이지, 2 힙, 3 오버플로, 4 B+Tree 내부, 5 B+Tree 리프, 6 인덱스 정의 |
| 5 | 1 | 플래그. 인덱스 정의의 bit 0은 유일 인덱스 |
| 6 | 2 | 항목 수 |
| 8 | 4 | 다음 페이지. 인덱스 정의에서는 트리 루트 |
| 12 | 4 | 이전 페이지(힙/리프만 사용) |
| 16 | 4 | 소유 저장소 루트 번호(카탈로그 오버플로는 0) |
| 20 | 2 | 힙 슬롯 디렉터리 끝 |
| 22 | 2 | 힙 데이터 시작 |
| 24 | 4 | 오버플로 데이터 길이 / 내부 노드의 첫 자식 |
| 28 | 4 | 예약, 0 |
| 32 | 8156 | 본문 |
| 8188 | 4 | CRC-32 |

빈 페이지는 오프셋 8로 다음 빈 페이지를 가리킨다. 재사용 전에 본문을 0으로 초기화한다. 헤더의 페이지 수를 넘는 포인터, 소유자가 다른 페이지, 순환 연결은 손상 오류이다. 파일의 끝을 줄이지 않고 빈 페이지를 재사용한다.

## 슬롯 힙과 오버플로

힙 루트도 데이터를 담는 슬롯 페이지이다. 힙 페이지는 양방향 연결 목록이다. 슬롯은 오프셋 32에서 위로 자라고 데이터는 8188에서 아래로 자란다. 갱신 때 데이터를 압축해 빈 공간을 회수하며 슬롯 번호는 유지한다. 삭제 슬롯은 재사용할 수 있다.

슬롯 하나는 12바이트이다: 데이터 오프셋(uint16), 페이지 내 데이터 길이(uint16), 첫 오버플로 페이지(uint32), 전체 행 바이트 수(uint32). 데이터 오프셋이 0이면 삭제 슬롯이다. 빈 바이트열도 활성 슬롯이며 오프셋이 8188이다. 한 행이 페이지에 맞지 않으면 전체 행을 오버플로 체인에 넣고 슬롯의 페이지 내 길이를 0으로 둔다. 오버플로 페이지는 오프셋 24에 길이를 적고 본문에 바이트열을 담는다. 삭제 및 갱신으로 불필요해진 오버플로 페이지는 빈 목록으로 돌려보낸다.

행 식별자는 `(pageId uint32, slotId uint16)`이다. 삭제 후 재사용한 식별자는 새 행을 뜻한다. 행 잠금과 인덱스 변경은 7단계에서 같은 논리 트랜잭션 안에 묶는다. 저장 계층은 SQL 컬럼을 해석하지 않는다.

## B+Tree

인덱스 정의 페이지 번호가 인덱스의 고정 식별자이다. 정의 페이지의 오프셋 8이 현재 트리 루트를 가리키므로 루트가 분할되어도 식별자는 바뀌지 않는다. 키 비교는 `Buffer.compare`이며 같은 키에서는 행 식별자 순으로 정렬한다. 복합 키, 컬럼별 ASC/DESC 및 NULL 순서 인코딩은 `types/codec.ts`의 책임이며 아래 "행과 인덱스 키의 값 인코딩"에 적었다. 유일 인덱스는 키만으로 중복을 검사한다.

리프 항목: 키 길이(uint32), 키 오버플로 포인터(uint32), 행 페이지(uint32), 행 슬롯(uint16), 예약(uint16), 인라인 키. 1,024바이트를 넘는 키는 인덱스 소유 오버플로 체인에 저장하며 인라인 키는 없다. 내부 항목은 리프 항목 뒤에 오른쪽 자식 번호(uint32)를 더한 형태이다. 내부 노드의 첫 자식은 공통 헤더 오프셋 24에 있다. 구분 키는 오른쪽 자식의 최소 `(키, 행 식별자)`이며 리프의 키 오버플로를 공유한다.

삽입은 바이트 크기를 기준으로 노드를 분할하고 필요하면 루트까지 전파한다. 삭제는 구분 키를 갱신하고 합친 내용이 한 페이지에 맞으면 형제 노드를 병합한다. 빈 노드를 회수하고 자식 하나인 루트는 축소한다. 노드의 최소 충전율은 강제하지 않으며 모든 리프의 깊이는 같다. 리프의 양방향 목록으로 범위 조회한다. 키 길이는 uint32의 범위이며 페이지 하나의 크기로 제한하지 않는다.

## 행과 인덱스 키의 값 인코딩

저장 계층은 바이트열만 다루며, SQL 값을 바이트열로 바꾸는 일은 `src/types/codec.ts`가 한다. 이 인코딩도 포맷 v1의 일부이다. 값은 `conformValue`로 타입에 맞춘 뒤에 인코딩한다. 값의 실행 중 표현과 규칙은 [data-types.md](data-types.md)에 있다.

### 행 (`encodeRow`, `decodeRow`)

| 순서 | 내용 |
|---|---|
| 1 | 컬럼 수. 부호 없는 가변 길이 정수(LEB128, 7비트씩 낮은 자리부터) |
| 2 | NULL 비트맵. `ceil(컬럼 수 / 8)` 바이트. 컬럼 i는 `i / 8`번째 바이트의 `i % 8`번째 비트(낮은 비트부터)이며 1이면 NULL |
| 3 | NULL이 아닌 컬럼의 값을 컬럼 순서대로 |

저장된 컬럼 수가 테이블 정의보다 적으면 모자란 뒤쪽 컬럼은 NULL로 읽는다. 더 많거나, 값이 끊겼거나, 바이트가 남으면 손상(`XX001`)이다.

| 타입 | 값의 바이트 |
|---|---|
| `CHAR(n)` | UTF-8 바이트 수(가변 길이 정수) + UTF-8. 뒤쪽 채움 공백은 떼고 저장하며 읽을 때 n 코드 포인트까지 다시 채운다 |
| `VARCHAR(n)` | UTF-8 바이트 수(가변 길이 정수) + UTF-8 |
| `BINARY(n)`, `VARBINARY(n)` | 바이트 수(가변 길이 정수) + 바이트열 |
| `SMALLINT`, `INTEGER`, `BIGINT` | 2, 4, 8바이트 2의 보수 |
| `DECIMAL(p,s)` | 소수 자릿수 s에서의 unscaled 정수를 압축 정수로 |
| `REAL`, `DOUBLE PRECISION` | IEEE 754 4, 8바이트 |
| `BOOLEAN` | 1바이트. 0 거짓, 1 참 |
| `DATE` | int32. 1970-01-01부터의 일수 |
| `TIME(p)` | int64. 자정부터의 마이크로초 |
| `TIME(p) WITH TIME ZONE` | int64 UTC 기준 마이크로초(현지 시각 - 오프셋) + int16 오프셋(분) |
| `TIMESTAMP(p)` | int64. 1970-01-01 00:00:00부터의 벽시계 마이크로초 |
| `TIMESTAMP(p) WITH TIME ZONE` | int64 UTC 기준 마이크로초 + int16 오프셋(분) |
| `INTERVAL` 연-월 계열 | 개월 수를 압축 정수로 |
| `INTERVAL` 일-시간 계열 | 마이크로초를 압축 정수로 |

압축 정수는 길이 1바이트 뒤에 그 길이만큼의 2의 보수 바이트를 적은 것이다. 길이는 값을 담는 최소 바이트 수이며 0은 길이 0이다. 일-시간 계열 기간은 선행 정밀도 9에서 int64를 넘으므로 이 형식을 쓴다. 다른 정수와 마찬가지로 리틀 엔디언이다.

### 인덱스 키 (`encodeKey`)

키는 B+Tree가 `Buffer.compare`로 비교하므로, 바이트열의 순서가 곧 값의 정렬 순서가 되도록 만든다. 컬럼을 순서대로 이어 붙이며, 컬럼마다 표시 바이트 하나와 값이 온다.

- 표시 바이트 : `00` 값 있음, `01` NULL. NULL은 값을 적지 않는다. 그래서 NULL이 가장 큰 값이 된다.
- `DESC` 컬럼은 그 컬럼의 표시 바이트와 값의 모든 비트를 뒤집는다. 순서가 반대가 되고 NULL이 맨 앞에 온다.
- 값의 인코딩은 서로의 접두가 되지 않으므로 뒤 컬럼의 바이트가 앞 컬럼의 순서에 끼어들지 않는다.

| 타입 | 값의 바이트 |
|---|---|
| `CHAR(n)` | 뒤쪽 공백을 뗀 UTF-8을 끝 표시 형식으로. (`CHAR`끼리는 뒤쪽 공백을 무시하고 비교한다) |
| `VARCHAR(n)` | UTF-8을 끝 표시 형식으로 |
| `BINARY(n)`, `VARBINARY(n)` | 바이트열을 끝 표시 형식으로 |
| `SMALLINT`, `INTEGER`, `BIGINT` | 2, 4, 8바이트 순서 보존 정수 |
| `DECIMAL(p,s)` | 소수 자릿수 s에서의 unscaled 정수를 순서 보존 정수로. 폭은 p ≤ 2이면 1, p ≤ 4이면 2, p ≤ 9이면 4, p ≤ 18이면 8, 그 밖에는 16바이트 |
| `REAL`, `DOUBLE PRECISION` | IEEE 754 빅 엔디언. 양수와 0은 부호 비트를 세우고, 음수는 모든 비트를 뒤집는다. 음의 0은 0으로 적는다 |
| `BOOLEAN` | 1바이트. 0 거짓, 1 참 |
| `DATE` | 4바이트 순서 보존 정수 |
| `TIME`, `TIMESTAMP` | 마이크로초를 8바이트 순서 보존 정수로. `WITH TIME ZONE`은 UTC 기준 마이크로초만 적고 오프셋은 넣지 않는다 (오프셋만 다른 같은 시각은 같은 값이다) |
| `INTERVAL` 연-월 계열 | 개월 수를 8바이트 순서 보존 정수로 |
| `INTERVAL` 일-시간 계열 | 마이크로초를 12바이트 순서 보존 정수로 |

- 순서 보존 정수 : 빅 엔디언 2의 보수에서 부호 비트를 뒤집은 것.
- 끝 표시 형식 : 본문의 `00`은 `00 FF`로 적고 끝에 `00 00`을 붙인다. 짧은 쪽이 앞서는 사전식 순서가 유지된다.

앞쪽 컬럼만으로 만든 접두 키로 범위를 탐색할 수 있다. 접두 키로 시작하는 키의 범위는 `[접두 키, prefixUpperBound(접두 키))`이다.

## 버퍼 캐시와 디스크 반영

동기 파일 I/O를 사용하며 초기 버전의 작은 동시 사용자 범위에서 커밋 작업을 한 이벤트 루프 안에서 직렬 처리한다. 깨끗한 페이지는 크기 제한 LRU 캐시에 두고 읽기 결과는 복사해 반환한다. 변경은 배치별 사본에만 두며 dirty 페이지를 캐시 퇴거 시 파일에 쓰지 않는다. 배치는 자신이 바꾼 페이지와 최신 커밋 페이지를 읽는다. 다른 배치는 미커밋 사본을 볼 수 없다. 롤백은 사본을 버리고 파일에는 아무것도 쓰지 않는다.

배치 시작 후 다른 배치가 커밋했다면 현재 배치의 커밋을 충돌 오류로 거부한다. 이 검사는 페이지 갱신 유실과 할당 충돌을 막는 저장 계층의 검증이다. 7단계 SQL 트랜잭션은 긴 수명의 페이지 배치를 사용하지 않고, 행 변경을 보관했다가 커밋 직전에 최신 페이지 위에서 짧은 저장 배치를 구성한다. 커밋은 데이터 페이지 → 파일 헤더 → fsync → 캐시 공개 순이다. I/O 실패 뒤에는 캐시를 사용 불가로 두어 불완전한 내용을 정상 데이터로 노출하지 않는다. 여러 파일 커밋은 7단계에서 직렬 조정하며 장애 원자성은 보장하지 않는다. WAL과 자동 복구는 초기 버전 범위 밖이다.

## 트랜잭션과 잠금 설계(7단계 구현)

- 커밋된 행과 별도로 트랜잭션별 행 변경 맵을 둔다. INSERT, UPDATE, DELETE 및 인덱스 변경은 한 맵에 묶는다. 조회는 문장 시작 시 커밋된 행 스냅샷에 자신의 변경을 합친다(READ COMMITTED).
- 문장 및 세이브포인트 시작 시 undo 목록 위치를 기록한다. 변경 전 값을 메모리 undo 목록에 넣고 실패한 문장은 해당 위치까지 되돌린다. 트랜잭션 전체 롤백은 전부 되돌린다. 미커밋 내용은 데이터 파일에 쓰지 않는다.
- 잠금 키는 `(테이블스페이스, 테이블, 행 식별자)`이다. 삽입과 PK 중복 경쟁에는 PK 키 잠금도 사용한다. 잠금은 커밋/롤백까지 보유하고 일반 SELECT는 기다리지 않는다. 대기 그래프와 제한 시간으로 교착 및 시간 초과를 처리한다.
- 커밋 잠금 아래에서 최신 커밋 값에 변경을 다시 적용하고 PK/FK를 검증한다. 저장 배치의 힙과 인덱스를 함께 갱신하고 fsync 후 논리 커밋을 공개한다.
- DDL은 객체 단위 배타 잠금을 쓰고 해당 객체에 미커밋 변경/행 잠금이 있으면 완료를 기다린다. DDL 전후의 자동 커밋을 적용한다.
- 연결 종료 및 정상 서버 종료는 논리 변경을 롤백한다. 디스크 반영 도중 중단되면 일부만 기록될 수 있으므로 정상 종료 플래그와 체크섬으로 감지하고 자동 복구하지 않는다.

## 오류와 호환성

저장 오류 번호: 1000 I/O(`58030`), 1001 손상(`XX001`), 1002 잘못된 저장 API 인자(`22023`), 1003 저장 배치 충돌(`40001`), 1004 유일 키 중복(`23505`). 지원하지 않는 버전/캐릭터셋/기능은 기존 1번(`0A000`)을 쓴다. 데이터 파일에는 포트 번호를 넣지 않는다.

`test/fixtures/storage-v1.hwdb`는 헤더, 힙(빈 행/UTF-8/큰 행), 카탈로그와 유일/일반 인덱스를 포함하는 고정 자료이다. 테스트는 복사본만 열고 원본 해시와 내용을 검증한다. 향후 버전에서도 이 자료로 v1 호환성을 검사한다.

개요 3의 예외에 따라 RDBMS 1.0 출시 전에는 포맷 번호를 올리지 않는 구조 변경과 기존 호환성 생략이 가능하다. 그런 변경은 문서와 호환성 자료를 함께 의도적으로 갱신한다. 1.0 이후에는 릴리스된 버전의 자료를 그대로 보관한다.

## API 사용 원칙

상위 계층은 `storage/format/format.ts`의 `createTablespace`, `openTablespace`, `Tablespace`, `StorageBatch`를 사용한다. `Tablespace.heap/index`는 읽기 전용이고 변경은 `begin()`으로 만든 배치의 `heap/index`를 통해 한다. 배치에서 오류가 나면 호출자가 롤백한다. SQL의 문장별 undo와 잠금은 7단계의 책임이다. 테이블스페이스 파일은 호출자가 독점 사용해야 하며 데몬에서는 데이터 디렉토리 잠금을 먼저 확보한다.

```ts
const space = createTablespace(filePath, { name: "APP" });
const batch = space.begin();
try {
  const root = batch.createHeap();
  const row = batch.heap(root).insert(Buffer.from("Hello World", "utf8"));
  batch.commit();
  const bytes = space.heap(root).get(row);
} catch (error) {
  batch.rollback();
  throw error;
} finally {
  space.close();
}
```
