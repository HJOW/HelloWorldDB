# HelloWorldDB 프로토콜 명세 (버전 1)

`rdbms` 서버와 클라이언트(접속용 CLI `hwdb`, Node.js 드라이버, 앞으로의 JDBC 와 DB툴)가 주고받는 메시지의 규약이다.

JDBC 클라이언트는 `jdbc6`(자바 6~7용 JDBC 4.0, 자바 8 이상 실행 호환)와 `jdbc8`(자바 8 이상용 JDBC 4.2)이다. 자바 5는 지원하지 않는다. 두 드라이버 모두 이 프로토콜을 사용하며 JDBC 인터페이스 버전 때문에 서버 프로토콜을 나누지 않는다. 지원 기준은 [AGENTS.md 상세 8-1](../../AGENTS.md#8-1-jdbc-드라이버-지원-기준)이다.
**모든 드라이버는 이 문서를 기준으로 구현한다.** 이 문서가 바뀌면(필드의 뜻을 바꾸거나 지우면) 프로토콜 버전을 올리고, 영향을 받는 드라이버 프로젝트의 PROGRESS.md 에 알린다.
필드를 더하는 것은 버전을 올리지 않는다. 받는 쪽이 모르는 필드를 무시하기 때문이다.

- 사양의 기준 : AGENTS.md 상세 6, 7, 8, 9, 14, 15
- 구현 : `rdbms/src/net/protocol.ts`(메시지 정의와 검증), `framing.ts`, `udpReliability.ts`, `messageHandler.ts`(서버), `rdbms/src/client/`(클라이언트). 설계 배경은 [communication-design.md](communication-design.md)이다.
- 시험 : `rdbms/test/net/`, `rdbms/test/daemon/serverAssembly.test.ts`

## 1. 개요

- 접속 경로는 셋이고, 어느 경로든 메시지, 세션, 인증, 권한 동작이 같다.

| 경로 | 용도 | 전송 | 암호화 |
|---|---|---|---|
| 로컬 전용 채널 | `hwdb`(SQL 접속과 데몬 제어) | 프레임(2-1) | 없음. 장비 밖으로 나가지 않는다 |
| TCP | 드라이버 | 프레임(2-1). `tcp.ssl` 이 있으면 포트 전체가 TLS | TLS(선택) |
| UDP | 드라이버 | 신뢰성 계층 위의 패킷(2-4) | 없음. **신뢰할 수 있는 네트워크에서만 쓴다** |

- 메시지는 UTF-8 JSON 객체 하나이다. 최대 크기는 16 MiB(16,777,216바이트)이다. 올바르지 않은 UTF-8 은 위반이다.
- 인스턴스는 포트 번호 하나로 식별한다. TCP 와 UDP 가 같은 번호를 쓰고, 로컬 전용 채널의 주소도 그 번호로 정해진다. 접속 정보에 SID 나 데이터베이스 이름은 없다.
- 요청 하나에 응답 하나가 짝지어지며 `id` 로 연결한다. 서버가 먼저 보내는 메시지는 `id: 0` 이다.
- 한 접속의 요청은 도착 순서대로 하나씩 처리한다. 클라이언트가 응답을 기다리지 않고 요청을 이어 보내도(파이프라이닝) 응답은 요청 순서대로 온다.

## 2. 전송 계층

### 2-1. 프레임 (로컬 전용 채널과 TCP)

`본문 길이(uint32, 빅엔디언)` + `JSON 본문` 이 메시지 하나이다.

- 길이는 본문을 모으기 **전에** 검사한다. 한도를 넘거나 길이가 0 이면 본문을 받지 않고 위반 오류(`08P01`, `id: 0`)를 보낸 뒤 접속을 닫는다.
- 한도는 접속 상태에 따라 다르다. **인증을 마치기 전 64 KiB**(65,536바이트), 인증 후 16 MiB.
- 한 번의 읽기에 여러 메시지가 오거나 한 메시지가 여러 번에 나뉘어 올 수 있다. 해석기는 둘 다 처리해야 한다.
- 서버는 `setNoDelay(true)` 와 `setKeepAlive(true, 30000)` 를 쓴다. 보내기가 밀리면(`write` 가 false) 그 접속의 다음 요청 처리를 멈춘다.

### 2-2. TLS (TCP)

- config.json 의 `tcp.ssl.certPath` 와 `keyPath`(PEM)가 모두 있으면 **TCP 포트 전체를 TLS 로** 운영한다. 평문 접속은 받지 않는다. 하나만 있으면 구동에 실패한다.
- 최소 버전은 `tcp.ssl.minVersion`(기본 `TLSv1.2`)이다. 최대 버전은 제한하지 않는다. TLS 1.2를 쓸 수 없는 자바 6 클라이언트를 받아야 하면 `TLSv1`로 낮춘다. 낮추면 그 버전의 암호 스위트도 허용하고(OpenSSL 3은 `@SECLEVEL=0`) 구동 로그에 경고를 남긴다.
- 인증서와 키는 구동할 때 한 번 읽는다. 갱신하려면 재시작한다. 암호가 걸린 키는 지원하지 않는다.
- **클라이언트는 서버 인증서를 기본으로 검증해야 한다.** 신뢰할 CA 를 지정하는 방법과 검증을 끄는 방법을 함께 제공한다(끄는 것은 명시했을 때만).
  - 검증 대상 : 신뢰하는 CA 에서 발급, 유효 기간, 접속 대상의 이름(호스트 이름 또는 IP)이 인증서의 이름과 일치.
  - **재시도 규칙** : 인증서 오류로 TLS 핸드셰이크가 실패하면 연결을 닫고 **100 ms** 뒤에 **새 연결**로 다시 시도한다. 재시도는 **최대 2회**(연결 시도는 최대 3번)이다.
    재시도에서도 검증은 그대로 한다. 인증서 오류가 아닌 실패(연결 거부, 시간 초과, 연결 끊김, TLS 버전 불일치, 서버가 TLS 가 아님)에는 재시도하지 않는다.
    모든 시도가 실패하면 `08001`(내부 번호 8007) 오류이고, 메시지에 시도 횟수와 원인 코드를 싣는다.
  - 인증서 오류 코드 : `CERT_HAS_EXPIRED`, `CERT_NOT_YET_VALID`, `DEPTH_ZERO_SELF_SIGNED_CERT`, `SELF_SIGNED_CERT_IN_CHAIN`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `UNABLE_TO_GET_ISSUER_CERT`,
    `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`, `CERT_UNTRUSTED`, `CERT_REVOKED`, `ERR_TLS_CERT_ALTNAME_INVALID`. (Node.js 의 코드이다. 다른 언어의 드라이버는 같은 뜻의 오류에 대응시킨다)
  - 인증서 검증은 핸드셰이크 안에서 끝나므로 재시도 시점에는 `hello`, 사용자 이름, 비밀번호가 서버에 가지 않았다.

### 2-3. 로컬 전용 채널

- 주소 : Windows 는 네임드 파이프 `\\.\pipe\helloworlddb-<포트>`, 그 외는 유닉스 도메인 소켓 `/tmp/helloworlddb-<포트>.sock`.
- 설정(`tcp`, `udp`, SSL)과 무관하게 **항상** 열린다. 열지 못하면 구동에 실패한다.
- 이 채널로 들어온 접속은 항상 로컬 접속이고, `maxConnections` 에 세지 않으며, 데몬 제어 요청(13절)을 받을 수 있다. 사용자 이름과 비밀번호 인증은 다른 경로와 똑같이 거친다.
- 유닉스 소켓 파일의 권한은 0600 이다. 클라이언트는 연결하기 전에 소켓 파일의 소유자가 자기 uid 인지 확인한다.

### 2-4. UDP

UDP 는 유실, 중복, 순서 뒤바뀜이 있고 패킷 크기에 제한이 있으므로 그 위에 신뢰성 계층을 둔다. 메시지(JSON 본문 하나) 단위로 전달을 보장한다.

#### 패킷 레이아웃 (빅엔디언, 헤더 20바이트)

| 오프셋 | 크기 | 필드 | 설명 |
|---|---|---|---|
| 0 | 2 | `magic` | `0x4857`(ASCII `HW`). 다르면 버린다 |
| 2 | 1 | `version` | 전송 계층 버전. 1. 다르면 버린다 |
| 3 | 1 | `flags` | `0x01 SYN`, `0x02 ACK`, `0x04 DATA`, `0x08 FIN`, `0x10 RST`. 모르는 비트가 있으면 버린다 |
| 4 | 4 | `sessionId` | 서버가 발급한 세션 번호. 세션을 열기 전의 클라이언트 패킷은 0 |
| 8 | 4 | `seq` | 메시지 번호. DATA 는 보내는 쪽이 **방향별로 1부터** 늘린다. ACK 는 확인하는 메시지의 번호 |
| 12 | 2 | `fragIndex` | 조각 번호(0부터). ACK 는 확인하는 조각의 번호 |
| 14 | 2 | `fragCount` | 그 메시지의 전체 조각 수(1 이상, 최대 65,535). ACK 에서는 0 |
| 16 | 4 | `ackSeq` | 이 패킷을 보내는 쪽이 **끝까지 받은** 상대 메시지의 가장 큰 번호(누적 확인). 없으면 0 |
| 20 | n | payload | DATA 의 조각 본문. DATA 가 아닌 패킷은 비어 있어야 한다 |

- 해석 규칙 : 길이 20 미만, 매직·버전 불일치, 모르는 플래그, DATA 인데 `fragCount` 가 0 이거나 `fragIndex >= fragCount` 이거나 본문이 빈 것, DATA 가 아닌데 본문이 있는 것은 **조용히 버린다**. 오류 응답 패킷은 `RST` 뿐이다.
- 패킷 하나의 최대 크기는 `udp.maxPacketSize`(기본 1200, 64 이상 65,507 이하)이다. 조각 본문은 `maxPacketSize - 20` 바이트까지이다. 서버는 이보다 큰 패킷을 버린다.
- 클라이언트는 처음에 1200바이트를 쓰고, `helloOk.udp.maxPacketSize` 를 알게 되면 둘 중 작은 값으로 맞춘다. 조각 수가 65,535 를 넘는 메시지는 보내지 않고 `54000` 이다.

#### 세션 열기와 닫기

1. 클라이언트가 `SYN|DATA`(`sessionId=0`, `seq=1`)로 `hello` 메시지를 보낸다. **방향마다 첫 번째 메시지(`seq` 1)의 모든 조각에 `SYN` 이 붙는다.**
2. 서버는 출발지 주소(IP:포트)로 대기 중인 세션을 찾는다. 있으면 같은 `SYN` 의 재전송이므로 그 세션으로 보낸다. 없으면 **암호학적 난수로 0 이 아닌 32비트 세션 번호**를 발급해 세션을 만든다.
   (인증을 마친 세션이 있는 주소에서 새 `SYN` 이 오면 같은 포트를 다시 쓴 새 접속으로 보고 옛 세션을 닫는다)
3. 서버의 모든 패킷은 세션 번호를 싣는다. 상대의 `SYN` 에 대한 ACK 에는 `SYN` 이 따라 붙는다. 클라이언트는 서버의 첫 패킷에서 세션 번호를 배우고, 이후 모든 패킷에 싣는다. 다른 번호의 패킷은 버린다.
4. 서버는 세션 번호 **와** 출발지 주소가 모두 맞을 때만 받아들인다. 주소가 다르면 **응답 없이 버린다**. 모르는 세션 번호에는 `RST`(헤더만 20바이트, 세션 번호를 되돌림)로 답한다. `RST` 에는 응답하지 않는다.
5. 닫을 때는 `FIN` 을 보낸다. 서버는 `FIN` 을 받으면 세션을 닫고(롤백) `FIN|ACK` 를 보낸다. 서버가 먼저 닫을 때도 보낸 것을 비운 뒤 `FIN` 을 보낸다. 클라이언트는 `RST` 나 `FIN` 을 받으면 접속이 끝난 것이다.

#### 송신자 (방향마다 하나)

- **한 번에 메시지 하나만** 전송 중으로 둔다. 다음 메시지는 대기열에서 기다린다. (요청과 응답이 한 번에 하나씩이라 처리량 손실이 없고 수신 쪽 순서 보장이 단순하다)
- 한 메시지 안에서 동시에 미확인으로 둘 수 있는 조각은 최대 **32개**이다. 조각마다 ACK 가 오면 창이 움직인다.
- 재전송 : 조각마다 보낸 시각을 기록하고 RTO 안에 ACK 가 없으면 그 조각을 다시 보낸다. RTO 는 RFC 6298 방식이다. 재전송하지 않은 조각의 왕복 시간만 표본으로 쓰고(Karn), 초기값 300 ms, 하한 50 ms, 상한 3 s, 같은 조각을 재전송할 때마다 2배(상한까지)이다.
  한 조각이 **10번 재전송**되고도 ACK 가 없으면 상대가 사라진 것으로 보고 접속을 실패시킨다(클라이언트는 `08006`). 서버는 처음 보내는 응답(`helloOk`)이 한 번도 확인되지 않은 동안은 한도를 **4번**으로 낮춘다(위조된 출발지 주소의 `SYN` 으로 응답이 계속 나가는 증폭을 줄이기 위함).
- 누적 확인 : 상대 패킷의 `ackSeq` 가 현재 전송 중인 메시지 번호 이상이면 남은 조각의 ACK 가 유실되었어도 전송이 끝난 것으로 본다.
- 모든 패킷(DATA 와 ACK)이 `ackSeq` 를 싣는다.

#### 수신자 (방향마다 하나)

- 상태 : `expectedSeq`(다음에 완성할 메시지 번호, 처음 1), 현재 메시지의 조각 표.
- `DATA` 를 받으면
  - `seq < expectedSeq` : 이미 전달한 메시지의 중복이다. 조각은 버리되 **ACK 는 다시 보낸다**(상대의 ACK 가 유실되어 재전송한 경우).
  - `seq == expectedSeq` : 조각을 저장한다. 이미 있는 조각이면 중복이므로 무시하되 ACK 는 보낸다. 모든 조각이 모이면 순서대로 이어 붙여 위로 전달하고 `expectedSeq` 를 올린다.
    `fragCount` 가 처음 본 값과 다르거나 누적 크기가 한도(인증 전 64 KiB, 후 16 MiB)를 넘으면 위반이며 세션을 끊는다.
  - `seq > expectedSeq` : 송신 규칙상 올 수 없다. 버린다(ACK 도 보내지 않는다).
- 조각마다 **즉시** ACK 를 보낸다. (지연 ACK 없음) ACK 는 `ACK` 플래그, `seq`·`fragIndex` 는 확인하는 조각, `fragCount` 0, `ackSeq` 는 지금까지 끝까지 받은 번호이다.

#### 시간 제한과 세션 유지

- 서버는 `udp.sessionTimeoutMs`(기본 60,000) 동안 그 세션의 유효한 패킷(ACK 포함)이 하나도 없으면 세션을 닫는다(롤백). **문장을 실행하거나 기다리는 중인 세션은 제외한다.** `0` 은 시간 제한 없음이다(구동 로그에 경고).
- 클라이언트 라이브러리는 유휴 상태에서 `sessionTimeoutMs / 3` 마다 `ping` 메시지를 보낸다(`helloOk.udp.sessionTimeoutMs` 로 값을 안다). `ping` 은 서버의 `session.idleTimeoutMs`(유휴 세션 종료)를 되돌리지 않는다.
- 인증 전 세션은 인증 시간 제한(10초) 뒤에 지운다.

## 3. 메시지 공통

### 3-1. 봉투

```json
{ "id": 7, "type": "execute", "sql": "SELECT 1" }
```

| 필드 | 설명 |
|---|---|
| `id` | 요청마다 클라이언트가 붙이는 **1 이상의 정수**. 응답은 같은 `id` 를 싣는다. `0` 은 서버가 먼저 보내는 메시지(유휴 시간 초과, 서버 종료)에 쓴다 |
| `type` | 메시지 종류(문자열). 요청과 응답의 이름은 겹치지 않는다 |
| 그 밖 | 종류마다 정해진 필드. **모르는 필드는 무시한다**. 모르는 `type` 은 위반이다 |

- 필드 이름은 camelCase 이다.
- 서버는 JSON 을 해석한 뒤 종류별로 필드의 타입과 범위를 모두 확인한 다음에만 쓴다.
- **접속을 끊는 위반(`08P01`)** : 해석할 수 없는 JSON, 객체가 아닌 최상위 값, `id` 가 없거나 1 미만이거나 정수가 아님, 모르는 `type`, 현재 상태에서 받을 수 없는 메시지, 크기 초과, 잘못된 프레임.
- **그 요청만 실패(`22023` 등)** : 필드 값만 틀린 요청(예 : `fetchSize` 가 음수, `sql` 이 문자열이 아님). 인증 전에는 이것도 접속을 닫는다.
- SQL 과 문자열 파라미터에 짝이 맞지 않는 서러게이트(JSON 의 `\uD800` 이스케이프 등)가 있으면 `22021` 이다.

### 3-2. 프로토콜 버전 협상

- 이 문서의 프로토콜은 **버전 1** 이다.
- 클라이언트는 `hello.versions` 에 지원하는 버전을 싣는다. 서버는 공통 버전 중 가장 큰 것을 `helloOk.version` 으로 돌려준다. 공통 버전이 없으면 `0A000`(내부 번호 1)로 알리고 접속을 닫는다.

## 4. 접속 상태

```
            hello             authStart             authFinish(성공)
  NEW ───────────────▶ GREETED ───────────▶ CHALLENGED ───────────────▶ READY
   │                      │                    │                          │ execute, fetch,
   │                      │ control            │ authFinish(실패)          │ closeCursor, ping
   │                      │ (로컬 채널만)        ▼                          │
   └──────────────────────┴───────────── close / 전송 끊김 / 시간 초과 ────────┴──▶ CLOSED
```

| 상태 | 받을 수 있는 메시지 |
|---|---|
| `NEW` | `hello` |
| `GREETED` | `authStart`, `control`(로컬 전용 채널만), `close` |
| `CHALLENGED` | `authFinish`, `close` |
| `READY` | `execute`, `fetch`, `closeCursor`, `ping`, `close` |

- 상태에 맞지 않는 메시지는 `08P01` 오류를 보내고 접속을 끊는다. (`control` 은 예외로 13절)
- `NEW` 가 시작되면 **인증 시간 제한 10초**가 돌고 `READY` 가 되면 풀린다. 넘으면 **오류 없이** 접속을 닫는다.
- 인증이 실패하면 오류를 보내고 **접속을 끊는다.** 같은 접속으로 다시 시도할 수 없다.
- 인증 전 접속 수는 TCP, UDP 합쳐 동시에 `max(16, 2 × maxConnections)` 개까지이다. 넘는 새 접속은 응답 없이 바로 닫는다. 로컬 전용 채널은 이 제한을 받지 않는다.
- 한 접속에서 처리를 기다릴 수 있는 요청은 64개이다. 넘으면 `53400`(`id: 0`)으로 접속을 끊는다. `close` 는 대기열을 건너뛰어 바로 처리한다.

## 5. 요청 메시지

| `type` | 필드 | 설명 |
|---|---|---|
| `hello` | `versions: number[]`(1~32개), `client?: string`, `mechanisms?: string[]` | 버전과 인증 방식 협상. `mechanisms` 를 생략하면 `["SCRAM-SHA-256"]` |
| `authStart` | `mechanism: "SCRAM-SHA-256"`, `clientFirst: string`, `tablespace?: string`, `timeZone?: string` | SCRAM client-first-message. `tablespace` 는 접속 직후의 현재 테이블스페이스(CLI 의 `-t`), `timeZone` 은 세션 타임존 |
| `authFinish` | `clientFinal: string` | SCRAM client-final-message |
| `execute` | `sql: string`, `params?: Param[]`, `fetchSize?: number` | 문장 **하나** 실행. `params` 는 최대 65,535개 |
| `fetch` | `cursor: number`, `fetchSize?: number` | 커서의 다음 행 묶음 |
| `closeCursor` | `cursor: number` | 커서 닫기 |
| `ping` | (없음) | 세션 유지 확인. 유휴 시간을 되돌리지 않는다 |
| `close` | (없음) | 정상적인 접속 종료. `bye` 로 답한 뒤 서버가 접속을 닫는다. 서버는 커밋하지 않은 변경을 롤백한다 |
| `control` | `action: "status" \| "stop"`, `token: string` | 데몬 제어. 13절 |

- `fetchSize` 는 1 이상의 정수이다.

## 6. 응답 메시지

| `type` | 필드 | 응답하는 요청 |
|---|---|---|
| `helloOk` | `version`, `server: string`, `mechanism: "SCRAM-SHA-256"`, `maxMessageBytes`, `defaultFetchSize`, `udp?: { sessionTimeoutMs, maxPacketSize }` | `hello`. `udp` 는 UDP 접속에만 있다 |
| `authChallenge` | `serverFirst: string` | `authStart` |
| `authOk` | `serverFinal: string`, `session: SessionInfo` | `authFinish` |
| `rows` | `columns?: ColumnMeta[]`, `rows: Value[][]`, `cursor?: number`, `hasMore: boolean` | `execute`, `fetch` (조회 결과) |
| `ok` | `message: string`, `rowCount?: number` | `execute` (조회가 아닌 문장) |
| `cursorClosed` | (없음) | `closeCursor` |
| `pong` | (없음) | `ping` |
| `bye` | `rolledBack?: true` | `close`. 세션을 닫으면서 커밋하지 않은 변경을 롤백했을 때만 `rolledBack` 이 있다. 클라이언트(`hwdb`)가 종료 때 이를 알린다 |
| `status` | `running, port, pid, startedAt, version, dataDir, tcpEnabled, udpEnabled, sessionCount, ready, systemPasswordInitial` | `control` + `status` |
| `stopping` | (없음) | `control` + `stop` |
| `error` | 11절 | 어느 요청에든 |

- `SessionInfo` : `{ id: number, user: string, tablespace: string | null, timeZone: string, autocommit: boolean }`. **현재 테이블스페이스가 없는 사용자의 `tablespace` 는 `null`** 이다. 드라이버와 DB툴은 이를 처리해야 한다.
- `rows` 의 `columns` 는 `execute` 의 응답에만 있고 `fetch` 의 응답에는 없다. `cursor` 는 남은 행이 있을 때(`hasMore: true`)만 있다.
- DML 의 `ok` 에는 영향받은 행 수 `rowCount` 가 있다.

## 7. 인증 (SCRAM-SHA-256)

RFC 5802(SCRAM), RFC 7677(SCRAM-SHA-256)을 따른다. 채널 바인딩은 쓰지 않는다(gs2 헤더 `n,,`). 비밀번호는 평문으로 어디에도 오가지 않는다(암호화되지 않은 TCP 와 UDP 에서도).

```
클라이언트                                              서버
  hello {versions}                          ─────────▶
                                            ◀─────────  helloOk
  authStart {clientFirst, tablespace?}      ─────────▶
                                            ◀─────────  authChallenge {serverFirst}
  authFinish {clientFinal}                  ─────────▶  증명 검증 → 로컬 판정 → CONNECT 검사 → 접속 수 제한 → 세션 생성
                                            ◀─────────  authOk {serverFinal, session}
```

- `clientFirst` : `n,,n=<사용자 이름>,r=<클라이언트 nonce>`. 사용자 이름의 `=` 는 `=3D`, `,` 는 `=2C` 로 적는다.
- `serverFirst` : `r=<클라이언트 nonce + 서버 nonce>,s=<솔트(base64)>,i=<반복 횟수>`
- `clientFinal` : `c=biws,r=<결합 nonce>,p=<클라이언트 증명(base64)>`. (`biws` 는 `n,,` 의 base64)
- `serverFinal` : `v=<서버 서명(base64)>`
- AuthMessage = `<client-first-message-bare>,<server-first-message>,<client-final-message-without-proof>`
- **클라이언트가 해야 하는 검증** : (1) 서버 nonce 가 **자기 nonce 로 시작하고 더 길어야** 한다. (2) 반복 횟수는 1 이상 10,000,000 이하여야 한다. (3) `authOk.serverFinal` 의 서명을 검증해 서버가 비밀번호를 아는지 확인한다.
  하나라도 어긋나면 접속을 끊고 `08006` 으로 실패시킨다.
- **사용자 이름** : 서버는 정확히 같은 이름을 먼저 찾고, 없으면 대문자로 바꾼 이름을 찾는다. (따옴표 없는 식별자는 대문자로 저장되므로 `system` 으로도 `SYSTEM` 에 접속된다)
- **인증 실패 응답은 하나이다** : `28000`, 내부 번호 7000, 메시지 `Authentication failed.` 사용자가 없는 경우, 비밀번호가 틀린 경우, nonce 나 채널 바인딩이 어긋난 경우가 모두 같다.
  없는 사용자에게도 가짜 검증 정보로 끝까지 진행하며(솔트는 같은 이름에 항상 같고, 반복 횟수는 SYSTEM 계정의 것과 같다) 응답 모양도 같다. 실패하면 **응답 전에 200 ms** 늦춘 뒤 오류를 보내고 접속을 끊는다.
- **인증이 성공한 뒤의 거부는 인증 실패와 구별한다**(비밀번호를 맞게 낸 사람에게만 알려지므로) : 로컬이 아닌데 CONNECT 가 없으면 `28000`(7006), `maxConnections` 초과면 `53300`(8001), 없는 테이블스페이스면 `3D000`, 잘못된 타임존이면 `22009`. 모두 접속을 닫는다.
- 로컬 접속 판정 : 로컬 전용 채널은 항상 로컬. TCP, UDP 는 상대 주소가 `127.0.0.0/8`, `::1`, `::ffff:127.x.x.x` 일 때만 로컬이다. 서버 장비의 비루프백 주소(LAN IP 등)로 같은 장비에서 접속하면 원격이다. 로그인 시점에 한 번 판정한다.
- `maxConnections` 는 인증을 마친 TCP, UDP 세션 수의 상한이다. 로컬 전용 채널의 세션은 세지도 막지도 않는다. `hello` 에서 이미 가득 찼으면 일찍 `53300` 으로 거절하고, 세션을 만드는 마지막 단계에서 다시 확인한다.

## 8. 값 표현

사양 상세 8 : 정밀도를 잃지 않도록 BIGINT, NUMERIC, 날짜시간, INTERVAL 은 문자열로, 이진 값은 16진 문자열로 보내고 나머지는 JSON 기본 타입을 쓴다. 실제 타입은 컬럼 메타데이터에 적는다.
문자열 표기는 [data-types.md](data-types.md)의 표준 표기와 같다.

| 타입 | JSON 값 | 예 |
|---|---|---|
| NULL | `null` | `null` |
| `CHAR`, `VARCHAR`(`NCHAR`, `NVARCHAR` 포함) | 문자열. `CHAR` 는 공백으로 채운 값이다 | `"Hello World"`, `"ab  "` |
| `BINARY`, `VARBINARY` | **대문자** 16진 문자열 | `"AB12"` |
| `SMALLINT`, `INTEGER` | JSON 숫자 | `42` |
| `BIGINT` | 10진 문자열 | `"5000000000"` |
| `NUMERIC`, `DECIMAL` | 10진 문자열(소수 자릿수 유지) | `"1.50"` |
| `REAL`, `DOUBLE PRECISION` | JSON 숫자 (NaN, 무한대는 값이 될 수 없다) | `1.5` |
| `BOOLEAN` | `true`, `false` | `true` |
| `DATE` | `YYYY-MM-DD` | `"2026-10-15"` |
| `TIME` | `HH:MM:SS[.ffffff]`(선언 자릿수). `WITH TIME ZONE` 은 끝에 `+09:00` | `"13:05:07"` |
| `TIMESTAMP` | `YYYY-MM-DD HH:MM:SS[.ffffff]`(선언 자릿수). `WITH TIME ZONE` 은 끝에 `+09:00` | `"2026-10-15 13:05:07.250"` |
| `INTERVAL` | 표준 표기 | `"1-02"`, `"3 04:05:06.500000"` |

- 행은 컬럼 순서의 배열이다. `rows: [[1, "a"], [2, null]]`. 컬럼 이름을 행마다 반복하지 않는다. 빈 문자열은 NULL 과 다르다.
- **드라이버의 타입 변환**(`bigint`, 날짜 객체 등)은 각 드라이버의 정책이다. 이 클라이언트(`rdbms/src/client`)는 JSON 값을 그대로 돌려준다.

### 8-1. 컬럼 메타데이터

| 필드 | 설명 |
|---|---|
| `name` | 컬럼 이름 |
| `typeName` | 정규 타입 이름 : `SMALLINT`, `INTEGER`, `BIGINT`, `DECIMAL`, `REAL`, `DOUBLE PRECISION`, `CHAR`, `VARCHAR`, `BINARY`, `VARBINARY`, `BOOLEAN`, `DATE`, `TIME`, `TIME WITH TIME ZONE`, `TIMESTAMP`, `TIMESTAMP WITH TIME ZONE`, `INTERVAL` |
| `declared` | 선언 표기. 예 : `DECIMAL(10,3)`, `VARCHAR(100)`, `TIMESTAMP(3) WITH TIME ZONE` |
| `length` | 문자·이진 타입의 길이 |
| `precision`, `scale` | `DECIMAL` |
| `fractionalPrecision` | `TIME`, `TIMESTAMP`, `INTERVAL`(초가 있을 때)의 소수 초 자릿수 |
| `startField`, `endField`, `leadingPrecision` | `INTERVAL` |

해당하지 않는 필드는 생략한다. 질의 결과에서는 NULL 허용 여부를 알 수 없으므로 싣지 않는다(테이블 정의는 딕셔너리 뷰 `SYS_COLUMNS`).

## 9. 파라미터

`execute.params` 의 원소(`Param`)는 다음 중 하나이다. 문장의 `?` 와 개수가 맞아야 한다(아니면 `07001`).

| JSON | 서버가 만드는 값 |
|---|---|
| `null` | NULL |
| `true`, `false` | BOOLEAN |
| 정수 숫자(안전 정수 범위 ±2^53-1) | 64비트 정수. 컬럼 타입에 맞춘다 |
| 소수 숫자 | 배정도 부동소수 |
| 문자열 | **타입 없는 문자열**. 컬럼이나 식의 타입으로 해석한다 |
| `{ "binary": "AB12" }` | 이진 값(16진 문자열이어야 한다. 아니면 `22018`) |

- **BIGINT 와 NUMERIC, 날짜시간은 문자열로 보내는 것이 정확하다.** JSON 숫자는 안전 정수 범위를 넘으면 정밀도를 잃으므로, 서버는 안전 정수를 벗어난 JSON 숫자를 `22003` 으로 거부한다(조용히 반올림하지 않는다). 드라이버는 그 범위를 넘는 정수를 문자열로 보내야 한다.
- 문자열 파라미터는 SQL 과 같은 규칙으로 해석된다. (예 : `'2026-10-15'` 는 DATE 컬럼과 비교하면 DATE 로 읽는다)

## 10. 결과 전달과 커서

실행기는 결과 행을 모두 만들어 돌려준다. 서버는 그 행을 메모리에 쥔 채 **조금씩 나누어 보낸다.**

- 조회 결과가 한 묶음에 다 들어가면 `rows`(`hasMore: false`)로 끝난다. 아니면 첫 묶음과 함께 `cursor` 번호(접속 안에서 1부터 늘어나는 정수)와 `hasMore: true` 를 보낸다.
- `fetch` 는 다음 묶음을 보낸다. 마지막 묶음이면 `hasMore: false` 이고 `cursor` 가 없으며 서버가 커서를 지운다. 그 뒤의 `fetch` 는 `34000`(내부 번호 8004)이다.
- `closeCursor` 는 남은 행을 버린다. 이미 없는 커서를 닫는 것은 오류가 아니다.
- 커서는 접속이 끝나면 모두 버린다. **커밋과 롤백은 커서를 무효로 만들지 않는다.** 결과는 문장이 실행된 시점의 행을 복사해 둔 것이다("홀더블"). 새 `execute` 도 열려 있는 커서를 닫지 않는다.
- 접속 하나가 동시에 열어 둘 수 있는 커서는 **16개**이다. 넘으면 그 `execute` 를 `53400` 으로 거부한다.
- 묶음 크기 : 행 수는 `fetchSize`(없으면 `defaultFetchSize` 500, 상한 100,000), 바이트는 **1 MiB** 를 넘기기 직전에 멈춘다. 묶음에는 항상 행이 하나 이상 들어간다.
  행 하나만으로 한 메시지에 들어가지 않으면(16 MiB 에서 여유 4 KiB 와 컬럼 정보 크기를 뺀 값 초과) `54000`(내부 번호 8003)이다.
- 한계 : 결과 전체가 서버 메모리에 한 번 올라온다.

## 11. 오류 응답

```json
{ "id": 7, "type": "error", "sqlState": "42501", "code": 7001, "message": "Permission denied: ...", "position": { "line": 1, "column": 15, "offset": 14 } }
```

- `sqlState`(ANSI 5자리), `code`(내부 오류 번호), `message`(영문)는 서버의 오류를 그대로 싣는다. `position` 은 SQL 문장 안의 위치(줄과 칸은 1부터, `offset` 은 0부터, UTF-16 단위)이며 있을 때만 있다. 문법 오류는 항상 있다.
- 서버의 예상 밖 예외는 `XX000` 으로 알리고 접속을 끊는다. 스택이나 내부 경로는 싣지 않는다(서버 로그에만 남는다).
- 클라이언트는 `message` 를 번역하지 않고 `sqlState` 와 `code` 로 판단한다. 화면 문구의 번역은 클라이언트 자신의 문구에만 적용한다.
- **문장 오류는 접속을 끊지 않는다**(문법, 권한, 제약 위반, 잠금 대기 초과 `55P03`, 교착 `40P01` 등). 교착이면 서버가 그 트랜잭션을 이미 롤백했고 세션은 그대로이므로 같은 접속에서 다시 시도한다.
- **접속을 끊는 경우** : `08P01` 위반, `28000` 인증 실패와 CONNECT 거부, `53300` 접속 수 초과, `53400` 대기열 초과, `XX000`, 인증 시간 초과(오류 없이 닫음).
- **서버가 먼저 끊는 경우**는 `id: 0` 인 `error` 를 보내고 닫는다 : 서버 종료 `57P01`(6003), 유휴 시간 초과 `57P05`(8002).

### 11-1. 통신 계층의 오류 번호 (8000번대)

| 번호 | SQLSTATE | 뜻 |
|---|---|---|
| 8000 | `08P01` | 프로토콜 위반 |
| 8001 | `53300` | 접속 수 초과 (`maxConnections`) |
| 8002 | `57P05` | 유휴 시간 초과로 서버가 세션을 끊음 |
| 8003 | `54000` | 처리 한도 초과 (행 하나가 메시지에 안 들어감, UDP 조각 수 초과) |
| 8004 | `34000` | 커서가 없음 |
| 8005 | `53400` | 구성 한도 초과 (열린 커서 16개, 요청 대기열 64개) |
| 8006 | `08006` | 연결 실패 — **클라이언트가 만드는 오류**. UDP 재전송 한도, 연결 끊김, 응답 시간 초과, 서버 확인 실패. 서버는 보내지 않는다 |
| 8007 | `08001` | 접속을 맺지 못함 : TLS 서버 인증서 검증 실패 — **클라이언트가 만드는 오류**. 2-2 절의 재시도를 다 쓰고도 실패했을 때 |

앞 단계의 번호를 다시 쓰는 것 : 인증 실패 `28000`(7000), CONNECT 거부 `28000`(7006), 권한 없음 `42501`(7001), 서버 종료 `57P01`(6003), 프로토콜 버전 불일치 `0A000`(1), 파라미터 개수 `07001`(5008), 잘못된 필드 값 `22023`.

## 13. 데몬 제어 요청

`hwdb stop` 과 `hwdb status` 가 쓴다. DB 계정 인증은 거치지 않고 **제어 토큰**이 인증을 대신한다. (사양 상세 14-1)

- 제어 요청은 **로컬 전용 채널의 `GREETED` 상태**(`hello` 직후, 로그인하지 않은 상태)에서만 받는다. TCP, UDP 로 오거나 다른 상태에서 오면 `42501`(7001)이다. (로그인하지 않은 상태에서는 접속을 닫고, `READY` 세션이면 세션은 유지한다)
- 제어 토큰은 데이터 디렉토리의 잠금 파일(`helloworlddb.lock`)에 적힌 값이며 구동할 때마다 새로 만든다. 데이터 디렉토리를 읽을 수 있는 운영체제 사용자만 데몬을 제어할 수 있다.
  서버는 상수 시간으로 비교하고, 틀리면 인증 실패와 같은 오류(`28000`, 7000)로 접속을 끊는다. 로그에 토큰을 남기지 않는다.
- `action: "status"` → `status` 응답. 같은 접속을 이어서 쓸 수 있다. `ready` 는 모든 접속 경로가 열려 접속을 받을 수 있게 되었는지(구동 중에는 false, `hwdb start` 가 이것을 기다린다), `systemPasswordInitial` 은 SYSTEM 계정이 초기 암호 그대로인지(`hwdb` 가 변경을 안내한다)이다.
- `action: "stop"` → `stopping` 응답을 쓰고 flush 한 뒤 접속을 닫고 종료 절차를 시작한다. 클라이언트는 프로세스가 사라지는 것을 기다려 확인한다.
- 제어 요청은 `maxConnections` 와 인증 전 접속 수 제한을 받지 않는다.

## 14. 종료와 정리

| 상황 | 서버의 동작 |
|---|---|
| 클라이언트가 `close` 를 보냄 | `bye` 응답 후 세션 닫기(롤백, 잠금 해제), 접속 닫기 |
| TCP, 로컬 연결이 끊김 | 세션 닫기(롤백, 잠금 해제). 진행 중이던 문장의 잠금 대기는 취소된다 |
| UDP 에서 `udp.sessionTimeoutMs` 동안 수신 없음 | 세션 닫기. 문장을 실행 중인 세션은 제외 |
| 클라이언트가 UDP `FIN` 을 보냄 | 세션 닫기, `FIN\|ACK` |
| `session.idleTimeoutMs` 초과 | `id: 0` 오류 `57P05` 를 보내고 닫기 |
| 서버 정상 종료 | 새 접속 받기를 멈추고 세션을 모두 닫은 뒤(롤백) 접속마다 `id: 0` 오류 `57P01` 을 보내고 닫기. 데이터 파일 반영 뒤 정상 종료 표시를 쓴다 |
| 인증 시간 초과 | 오류 없이 접속 닫기 |

## 15. 클라이언트 구현 체크리스트

드라이버가 지켜야 하는 것이다. 참고 구현은 `rdbms/src/client/connection.ts`, `transports.ts`, `udpTransport.ts` 이다.

1. 연결 → `hello`(`versions: [1]`) → `helloOk` 확인 → `authStart` → 서버 nonce 와 반복 횟수 확인 → `authFinish` → 서버 서명 확인 → `authOk` 의 `session` 보관.
2. 요청마다 1부터 늘어나는 `id` 를 붙이고, 응답을 `id` 로 짝짓는다. `id: 0` 의 `error` 는 접속이 곧 닫힌다는 뜻이며 기다리던 모든 요청을 그 오류로 실패시킨다.
3. 접속이 끊기면 기다리던 모든 요청을 `08006` 으로 실패시킨다. 요청마다 선택적 제한 시간을 둘 수 있다.
4. TLS 는 서버 인증서를 기본으로 검증하고, 인증서 오류에만 100 ms 뒤 최대 2회 재시도한다(2-2절). 최종 실패는 `08001`(8007).
5. UDP 는 유휴 상태에서 `sessionTimeoutMs / 3` 마다 `ping` 을 보내고, 연결 시작과 끝에서 `hello`/`FIN` 을 쓴다. `RST` 를 받으면 접속이 끝난 것이다.
6. 큰 결과는 `cursor` 로 나누어 받는다. 더 필요 없으면 `closeCursor` 로 닫는다. 커서는 접속당 16개이다.
7. BIGINT, NUMERIC, 날짜시간을 파라미터로 보낼 때는 문자열을 쓴다. 안전 정수를 넘는 정수는 반드시 문자열이다.
8. 현재 테이블스페이스가 없는 세션(`tablespace: null`)을 처리한다.
9. 서버 오류 메시지는 번역하지 않고 `sqlState`, `code` 로 판단한다. `position` 이 있으면 SQL 의 해당 위치를 보여 줄 수 있다.

## 16. 알려진 한계와 런타임 차이

- UDP 는 암호화하지 않는다. 비밀번호는 SCRAM 이라 평문으로 가지 않지만 이후의 문장과 결과는 평문이다. UDP 의 상대 주소는 위조될 수 있으며, 운영체제는 보통 외부 인터페이스에서 들어온 루프백 출발지 패킷을 버리지만 보장되지 않는다.
- 유실이 아주 심한 망(지속적으로 30% 이상)에서는 재전송 한도(10번)를 넘어 접속이 끊길 수 있다. 정확성에는 영향이 없다(잘못된 데이터를 전달하지 않고 실패한다).
- 문장 실행은 한 스레드에서 동기로 도므로 오래 걸리는 문장 하나가 다른 접속의 응답과 ACK 처리를 늦춘다. UDP 의 RTO 가 헛되이 만료될 수 있으나 중복은 무시되므로 결과는 맞다.
- **bun 으로 데몬을 구동할 때**(2026-10-16 bun 1.3.14 확인) : 네임드 파이프, TCP, UDP, SCRAM, 프레임, 커서는 Node.js 와 같게 동작한다. TLS 는 최소 버전을 `tcp.ssl.minVersion` 대로 적용하지 못한다.
  bun 의 TLS 서버는 BoringSSL 의 기본값(TLS 1.2 이상)을 쓴다. 그래서 기본 설정(`TLSv1.2`)은 그대로 지켜지지만 `TLSv1.3` 으로 올려도 1.2 클라이언트를 받고, `TLSv1`·`TLSv1.1`(구버전 허용)은 켤 수 없다. (구동 로그에 경고한다. 필요하면 Node.js 로 구동한다)
  bun 의 TLS 클라이언트는 `minVersion`, `maxVersion` 옵션을 적용하지 않는다.
- Windows 는 TCP 와 UDP 에 서로 다른 "제외된 포트 범위"(`netsh int ipv4 show excludedportrange protocol=udp`)를 가지며 동적 포트 범위 안에 생기기도 한다. 그 범위의 포트를 `port` 로 쓰면 바인드가 `EACCES` 로 실패해 구동에 실패한다. 기본 포트 7410 은 해당하지 않는다.
- 리눅스, macOS 의 유닉스 소켓 처리(0600 권한, 남은 소켓 파일 정리, 소유자 확인)는 코드로만 작성되었고 Windows 개발 환경에서는 실행해 보지 못했다.
