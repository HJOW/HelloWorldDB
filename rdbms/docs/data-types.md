# 데이터 타입 정의

`src/types/dataType.ts`의 `resolveDataType()`은 SQL 타입 이름과 타입 인자를 정규화된 `DataType` 정의로 바꾼다. 키워드·별칭은 대소문자를 구분하지 않으며 연속 공백은 하나로 정규화한다. 타입 인자는 SQL 파서에서 숫자로 해석해 넘긴다.

| 정규 타입 | 별칭 | 기본값 | 허용 범위 |
|---|---|---|---|
| `CHAR` | `CHARACTER`, `NCHAR`, `NATIONAL CHARACTER` | 길이 1 | 1~2,000 |
| `VARCHAR` | `CHARACTER VARYING`, `CHAR VARYING`, `NVARCHAR`, `NATIONAL CHARACTER VARYING` | 길이 65,535 | 1~65,535 |
| `BINARY` | - | 길이 1 | 1~2,000 |
| `VARBINARY` | `BINARY VARYING` | 길이 65,535 | 1~65,535 |
| `SMALLINT` | - | - | 16비트 부호 정수 |
| `INTEGER` | `INT` | - | 32비트 부호 정수 |
| `BIGINT` | - | - | 64비트 부호 정수 |
| `DECIMAL` | `DEC`, `NUMERIC` | `(10,3)` | 정밀도 1~38, 소수 자릿수 0~정밀도 |
| `REAL` | - | - | IEEE 754 단정도 |
| `DOUBLE PRECISION` | - | - | IEEE 754 배정도 |
| `FLOAT(p)` | - | 인자 생략 시 `DOUBLE PRECISION` | p=1~24는 `REAL`, p=25~53은 `DOUBLE PRECISION` |
| `BOOLEAN`, `DATE` | - | - | 각각 논리값, 날짜 |
| `TIME(p)` | `TIME(p) WITH TIME ZONE` | p=0 | p=0~6 |
| `TIMESTAMP(p)` | `TIMESTAMP(p) WITH TIME ZONE` | p=6 | p=0~6 |
| `INTERVAL` 수식자 | - | 선행 정밀도 2, 초 정밀도 6 | 선행 정밀도 1~9, 초 정밀도 0~6 |

문자 길이는 바이트가 아니라 유니코드 코드 포인트 단위이다. `NCHAR`, `NVARCHAR`는 UTF-8만 지원하므로 각각 `CHAR`, `VARCHAR`와 같은 정의를 사용한다. `TIME WITH TIME ZONE`과 `TIMESTAMP WITH TIME ZONE`은 타임존이 있는 별도 타입 정의로 보존한다.

`DECIMAL`, `DEC`, `NUMERIC`의 인자 전체 생략은 `(10,3)`, 정밀도만 지정한 `(p)`는 `(p,0)`이다. `FLOAT(p)`는 IEEE 754 유효 정밀도 경계인 24비트 이하에서 단정도, 그 이상에서 배정도로 해석한다.

`resolveDataType()`에서 `INTERVAL` 수식자는 타입 이름에 붙여 전달한다(예: `INTERVAL YEAR TO MONTH`, `INTERVAL DAY TO SECOND`). 타입 인자는 선행 정밀도, 그리고 종료 필드가 `SECOND`일 때 초 소수 자릿수 순서이다. 시작 필드가 `SECOND`인 단일 필드 수식자는 인자를 초 소수 자릿수로 해석한다. 이 표기는 타입 해석 API의 내부 인터페이스이다.

SQL 구문 분석기는 이 표기를 거치지 않고 `resolveIntervalType(시작 필드, 종료 필드, 선행 정밀도, 소수 초 자릿수)`로 같은 정의를 만든다. SQL 구문은 `INTERVAL DAY(3) TO SECOND(2)`처럼 정밀도를 필드 뒤에 적으며, 단일 `SECOND`는 표준대로 `INTERVAL SECOND(선행 정밀도, 소수 초 자릿수)`이다. `TO`로 같은 필드를 다시 적은 것(`DAY TO DAY`)과 `SECOND`로 끝나지 않는 수식자의 소수 초 자릿수는 `22023`이다.

표준에 있는 `NATIONAL CHAR`, `NATIONAL CHAR VARYING`, `NCHAR VARYING`도 각각 `CHAR`, `VARCHAR`의 별칭으로 받는다.

잘못된 인자 수나 범위는 SQLSTATE `22023`, 내부 오류 번호 2000이다. 지원하지 않는 타입은 SQLSTATE `0A000`, 내부 오류 번호 1이다. `CLOB`, `NCLOB`, `BLOB`를 비롯해 AGENTS.md에서 초기 버전 제외로 정한 타입은 지원하지 않는다.

드라이버와 DB툴은 컬럼의 실제 길이/정밀도/소수 자릿수를 서버 메타데이터에서 읽어야 한다. 기본값은 타입 선언에만 적용하며 조회된 값의 형식을 강제로 바꾸는 규칙이 아니다.

SQL 카탈로그에는 해석한 타입 인자를 명시적으로 기록한다. 값의 저장 형식은 [storage-v1.md](storage-v1.md)의 "행과 인덱스 키의 값 인코딩"에 있으며 그 문서의 버전 규칙을 따른다. 1.0 출시 전에는 포맷 번호를 유지한 변경과 기존 호환성 생략이 가능하며, 이 경우에도 문서와 테스트 자료를 함께 갱신한다.

## 실행 중의 값 표현

`src/types/value.ts`의 `SqlValue`는 타입 꼬리표 없이 다음 JavaScript 값으로 SQL 값을 담는다. 타입 정의(`DataType`)는 값과 따로 다닌다.

| SQL 타입 | 표현 | 비고 |
|---|---|---|
| NULL | `null` | |
| `CHAR`, `VARCHAR` | `string` | `CHAR`는 선언 길이까지 공백으로 채운 값 |
| `BINARY`, `VARBINARY` | `Buffer` | `BINARY`는 선언 길이까지 `0x00`으로 채운 값 |
| `SMALLINT`, `INTEGER`, `BIGINT` | `bigint` | |
| `DECIMAL` | `Decimal` (`numeric.ts`) | `unscaled / 10^scale`. `bigint` 기반이며 부동소수를 거치지 않는다 |
| `REAL`, `DOUBLE PRECISION` | `number` | 유한한 값만. NaN과 무한대는 값이 될 수 없고, 음의 0은 0으로 통일한다 |
| `BOOLEAN` | `boolean` | |
| `DATE` | `DateValue` | 1970-01-01부터의 일수 |
| `TIME` | `TimeValue` | 자정부터의 마이크로초. `WITH TIME ZONE`은 UTC 기준 마이크로초와 오프셋(분) |
| `TIMESTAMP` | `TimestampValue` | 벽시계 마이크로초. `WITH TIME ZONE`은 UTC 기준 마이크로초와 오프셋(분) |
| `INTERVAL` | `IntervalValue` | 연-월 계열은 개월 수, 일-시간 계열은 마이크로초 |

달력은 전 기간에 그레고리력을 적용한다. JavaScript의 `Date`는 밀리초까지만 담으므로 값 표현으로 쓰지 않는다.

## 값을 타입에 맞추기

`conformValue(값, 타입)`이 길이·범위·정밀도를 확인한다. 값의 계열이 타입과 다르면 먼저 형변환해야 한다.

- 문자: 길이는 코드 포인트로 센다. 길이를 넘으면 잘라내지 않고 `22001`이다. 단, 넘는 부분이 모두 공백이면 그 공백만 뗀다(표준의 저장 대입 규칙이며 `CHAR`의 채움 공백 때문에 필요하다). 짝이 맞지 않는 서러게이트는 `22021`이다.
- 이진: 길이를 넘으면 `22001`이다.
- 정수: 범위를 넘으면 `22003`이다.
- `DECIMAL(p,s)`: 소수부를 s자리로 반올림(0에서 먼 쪽)한 뒤 정수부가 p-s자리를 넘으면 `22003`이다.
- 부동소수: NaN, 무한대, 단정도 범위를 넘는 값은 `22003`이다.
- `TIME`, `TIMESTAMP`: 소수 초를 선언 자릿수로 반올림한다. 반올림 결과가 24시(TIME) 또는 9999-12-31 이후가 되면 `22008`이다. 범위는 벽시계 날짜 0001-01-01 ~ 9999-12-31이며, 오프셋은 -23:59 ~ +23:59이다(`22009`).
- `INTERVAL`: 종료 필드보다 작은 단위는 0 방향으로 버리고 소수 초는 반올림한다. 선행 필드가 선행 정밀도를 넘으면 `22015`이다.

상세 1-2는 "NUMERIC의 소수부만 반올림한다"고 정했는데, 소수 초도 같은 성격의 소수부로 보아 반올림한다. 이는 Oracle, PostgreSQL, MySQL의 공통 동작이다.

## 비교와 정렬

- 한쪽이 NULL이면 비교 결과는 UNKNOWN이다(`compareNullable`). 정렬에서는 NULL을 가장 큰 값으로 본다(`compareForSort`). `NULLS FIRST`/`NULLS LAST`로 바꿀 수 있다.
- 문자열은 코드 포인트 순이며 대소문자를 구분한다. UTF-8 바이트 순서와 같다. JavaScript의 기본 문자열 비교는 UTF-16 단위라 보충 평면 문자의 순서가 다르므로 쓰지 않는다.
- 두 값이 모두 `CHAR`이면 뒤쪽 공백을 뗀 뒤 비교한다. `CHAR`와 `VARCHAR`를 비교할 때는 공백도 구별한다.
- 수 계열은 정수와 `DECIMAL`을 10진으로 정확히 비교한다. 부동소수가 섞이면 부동소수로 바꾸어 비교한다.
- `WITH TIME ZONE` 값은 UTC 기준 시각으로 비교한다. 오프셋만 다른 같은 시각은 같은 값이다.
- 계열이 다른 값은 형변환 없이 비교하지 않는다. 실행기가 `commonType`으로 공통 타입을 정해 먼저 바꾼다.

## 형변환

암묵적 형변환은 같은 계열 안에서만 한다(`isImplicitlyConvertible`). 계열은 다음과 같다.

| 계열 | 타입 |
|---|---|
| 문자 | `CHAR`, `VARCHAR` |
| 이진 | `BINARY`, `VARBINARY` |
| 수 | `SMALLINT`, `INTEGER`, `BIGINT`, `DECIMAL`, `REAL`, `DOUBLE PRECISION` |
| 논리 | `BOOLEAN` |
| 날짜 | `DATE`, `TIMESTAMP`, `TIMESTAMP WITH TIME ZONE` |
| 시각 | `TIME`, `TIME WITH TIME ZONE` |
| 연-월 기간 | `INTERVAL YEAR`, `MONTH`, `YEAR TO MONTH` |
| 일-시간 기간 | 그 밖의 `INTERVAL` |

좁은 타입으로 가는 암묵적 변환도 허용하며 범위는 실행할 때 확인한다. 계열이 다르면 `42804`이다.

`CAST`는 같은 계열 안의 변환에 더해 다음을 지원한다(`isCastSupported`). 그 밖의 조합은 `42846`이다.

- 문자 ↔ 이진을 제외한 모든 타입
- `TIMESTAMP` ↔ `TIME`
- 정수·`DECIMAL` ↔ 단일 필드 `INTERVAL` (그 필드 단위의 수)

변환 규칙:

- 수 → 정수: 0에서 먼 쪽으로 반올림한다(2.5 → 3, -2.5 → -3).
- 부동소수 → `DECIMAL`: 그 부동소수로 되읽히는 가장 짧은 10진 표기를 거친다(0.1 → 0.1).
- 문자열 → 정수는 정수 표기만, `DECIMAL`·부동소수는 지수 표기까지 받는다. 틀리면 `22018`이다.
- 문자열 → `BOOLEAN`: `TRUE`, `FALSE`만 받는다(대소문자 무관). `UNKNOWN`은 NULL이다.
- `CHAR` → `VARCHAR`: 채움 공백을 그대로 둔다.
- 날짜시간 문자열은 `YYYY-MM-DD`, `HH:MM[:SS[.ffffff]]`, `YYYY-MM-DD HH:MM[:SS[.ffffff]]` 형태이다. 날짜와 시각 사이는 공백이나 `T`, 뒤에 `Z`·`+09`·`+09:00`·`+0900` 오프셋을 둘 수 있다. 연도는 4자리이다. 형식이 틀리면 `22007`, 필드가 범위를 벗어나면 `22008`이다. `DATE`로 받을 때 시각이 적혀 있으면 날짜만 남긴다.
- 오프셋이 적힌 문자열이나 `WITH TIME ZONE` 값을 타임존 없는 타입으로 받으면 세션 타임존의 벽시계 시각으로 옮긴다. 반대 방향은 그 벽시계 시각을 세션 타임존의 시각으로 본다.
- `TIME` → `TIMESTAMP`: 날짜는 세션 타임존의 오늘이다.
- `INTERVAL` 문자열은 한정자에 맞는 형태(`Y-M`, `D H:M:S.f` 등)만 받는다. 형식이 틀리면 `22006`이다.
- 타입이 정해지지 않은 문자열(리터럴, 문자열로 받은 파라미터)은 `castLiteral`로 문맥의 타입에 맞추어 해석한다. 이진 타입은 16진 문자열로 읽는다.

문자열 표기(`formatValue`)는 `CAST(값 AS VARCHAR)`와 화면 출력이 함께 쓴다. `BOOLEAN`은 `TRUE`/`FALSE`, 이진은 대문자 16진, 날짜시간은 선언 자릿수의 소수 초를 포함한 ISO 8601 형태, `WITH TIME ZONE`은 `+09:00`을 붙인다.

## 타임존

`resolveTimeZone`은 `local`(서버 운영체제의 타임존), 오프셋(`+09:00`), IANA 지역 이름(`Asia/Seoul`)을 받는다. 해석할 수 없으면 `22009`이다. 지역 이름의 오프셋은 `Intl`로 구하며 분 단위로 반올림한다. 서머타임 종료로 두 번 나타나는 벽시계 시각은 먼저 오는 쪽으로, 시작으로 건너뛴 시각은 전환 이전의 오프셋으로 계산한다(결과는 전환 뒤의 시각으로 밀린다).

`WITH TIME ZONE` 값에 저장하는 오프셋은 입력 당시의 오프셋이며 지역 이름은 저장하지 않는다. 그래서 기간을 더해도 오프셋은 바뀌지 않는다.

형변환과 날짜시간 연산은 `TypeContext`(세션 타임존, 문장 시작 시각)를 받는다. 한 문장 안에서 현재 시각은 같은 값이다.

## 연산 결과의 타입

`src/types/arithmetic.ts`의 `bindArithmetic`, `bindNegate`, `bindConcat`이 인자 타입으로 결과 타입을 정하고, 행마다 `evaluate`로 계산한다. 인자가 NULL이면 결과는 NULL이다. 정의되지 않은 조합은 `42804`이다.

수 계열:

| 인자 | 결과 타입 | 비고 |
|---|---|---|
| 정수, 정수 | 둘 중 넓은 타입. 적어도 `INTEGER` | 나눗셈은 0 방향 버림. 넘치면 `22003` |
| `DECIMAL`이 낀 경우 | 아래 식 | 정수는 `DECIMAL(5,0)`, `(10,0)`, `(19,0)`으로 본다 |
| 부동소수가 낀 경우 | 둘 다 `REAL`이면 `REAL`, 아니면 `DOUBLE PRECISION` | 유한하지 않은 결과는 `22003` |

`DECIMAL(p1,s1)`과 `DECIMAL(p2,s2)`의 결과:

| 연산 | 소수 자릿수 | 정밀도 |
|---|---|---|
| `+`, `-` | max(s1, s2) | max(p1-s1, p2-s2) + 소수 자릿수 + 1 |
| `*` | s1 + s2 | p1 + p2 + 1 |
| `/` | max(6, s1 + p2 + 1) | (p1-s1) + s2 + 소수 자릿수 |

정밀도가 38을 넘으면 38로 맞추고, 정수부 자릿수를 먼저 지키며 소수 자릿수를 줄인다. 단 소수 자릿수는 min(원래 값, 6) 아래로 줄이지 않는다. 계산은 정확히 한 뒤 결과 타입에 맞추므로, 소수부는 반올림되고 정수부가 넘치면 `22003`이다. 0으로 나누면 타입과 무관하게 `22012`이다.

날짜시간과 기간:

| 연산 | 결과 타입 |
|---|---|
| `DATE ± 정수`, `정수 + DATE` | `DATE` (정수는 일수) |
| `DATE - DATE` | `INTEGER` (일수) |
| `DATE ± 연-월 기간`, `DATE ± INTERVAL DAY` | `DATE`. 결과 달에 그 날이 없으면 말일 |
| `DATE ± 시각 필드가 있는 기간` | `TIMESTAMP(기간의 소수 초 자릿수)` |
| `TIMESTAMP ± 기간` | 같은 타임존 속성의 `TIMESTAMP`. 소수 초 자릿수는 둘 중 큰 값 |
| `TIME ± 일-시간 기간` | `TIME`. 24시를 넘으면 하루를 돌아 다시 센다 |
| `TIMESTAMP - TIMESTAMP` (`DATE`가 섞여도 됨) | `INTERVAL DAY(9) TO SECOND(p)` |
| `TIME - TIME` | `INTERVAL HOUR(9) TO SECOND(p)` |
| `기간 ± 기간` (같은 계열) | 두 한정자의 필드를 모두 담는 기간. 선행 정밀도 9 |
| `기간 * 수`, `수 * 기간`, `기간 / 수` | 같은 한정자의 기간. 선행 정밀도 9 |

기간은 좌우를 바꾸어 `기간 + 날짜시간`으로도 쓸 수 있다. 계산으로 얻은 기간은 결과 한정자에 맞추므로 종료 필드보다 작은 단위는 버려진다(`INTERVAL '1' DAY / 2`는 0일이다). 타임존 유무가 다른 두 시각의 뺄셈은 세션 타임존으로 맞춘 뒤 계산한다. `DATE - DATE`와 `DATE ± 정수`는 표준에 없지만 Oracle과 PostgreSQL이 함께 제공하는 동작이라 넣었다.

단항 `-`는 수 계열과 기간에 정의된다. 정수의 결과는 적어도 `INTEGER`이다.

연결 `||`는 문자끼리 또는 이진끼리만 잇는다. 결과 길이는 두 길이의 합이고, 고정 길이끼리이며 합이 2,000 이하이면 고정 길이, 아니면 가변 길이(최대 65,535)이다. 실제 결과가 그 길이를 넘으면 `22001`이다.

## 공통 타입

`commonType`은 비교, `CASE`, `COALESCE`, 집합 연산에서 두 타입을 함께 다룰 타입을 정한다. 계열이 다르면 공통 타입이 없다.

- 문자·이진: 길이는 큰 쪽. 둘 다 고정 길이면 고정 길이, 아니면 가변 길이
- 수: 부동소수가 끼면 부동소수(둘 다 `REAL`일 때만 `REAL`), `DECIMAL`이 끼면 두 타입의 정수부와 소수부를 모두 담는 `DECIMAL`, 정수끼리는 넓은 쪽
- 날짜: `DATE`끼리는 `DATE`, 아니면 `TIMESTAMP`. 한쪽이라도 타임존이 있으면 `WITH TIME ZONE`
- 시각: 한쪽이라도 타임존이 있으면 `WITH TIME ZONE`
- 기간: 두 한정자의 필드를 모두 담는 한정자

## 타입 시스템의 오류 번호

| 번호 | SQLSTATE | 뜻 |
|---:|---|---|
| 2000 | `22023` | 잘못된 데이터 타입 인자 |
| 2001 | `22001` | 문자열이나 바이트열이 길이를 넘음 |
| 2002 | `22003` | 수가 범위나 정밀도를 넘음 |
| 2003 | `22012` | 0으로 나눔 |
| 2004 | `22018` | 문자열을 수·논리·16진 값으로 해석할 수 없음 |
| 2005 | `22007` | 날짜시간 문자열의 형식이 틀림 |
| 2006 | `22008` | 날짜시간 값이 범위를 넘음 |
| 2007 | `22006` | INTERVAL 문자열의 형식이 틀림 |
| 2008 | `22015` | INTERVAL 필드가 범위나 선행 정밀도를 넘음 |
| 2009 | `22009` | 타임존 지정이 틀림 |
| 2010 | `22021` | 올바르지 않은 UTF-8 또는 짝이 맞지 않는 서러게이트 |
| 2011 | `42804` | 타입이 맞지 않아 암묵적 형변환이나 연산을 할 수 없음 |
| 2012 | `42846` | 지원하지 않는 형변환 |
